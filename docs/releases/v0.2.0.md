# Akamata v0.2.0

A portable Zig backend framework for Native and Cloudflare Workers.
Requires **Zig 0.17.0**. This is a pre-1.0 minor feature/API-change release,
following the repository's `0.x.0` versioning policy.

## Highlights

Write an ordinary Zig function and register it as a typed HTTP endpoint:

```zig
fn hello() []const u8 { return "Hello, Akamata!"; }
pub const Application = ak.App(.{
    .routes = .{ ak.get("/", hello) },
});
```

Grow that application with explicit Path/Query/Header/Cookie/Json/Principal
parameters, ordinary DTO structs, validation rules, typed responses and
exhaustive HTTP error mappings. Existing App(State), Context, middleware,
manual Response and explicitly owned provider APIs remain available.

Endpoint metadata now connects those contracts to OpenAPI, generated TypeScript
clients, route/capability inspection and socket-free tests. Test identities and
MemoryStore/QueueRecorder assertions use existing typed ownership paths.

Portable Application/Production Contracts trace requirements to DB, Storage,
Queue and Realtime providers, bindings, owners, cleanup and local environment
validation. Storage gains explicit caller-owned listPage/pagination. Native
queues adapt the existing jobs.Queue engine. Workers uses existing D1/R2/Queue/
DO adapters and managed glue, with explicit lifecycle boundaries.

The default scaffold is a minimal Hello application with a working test step.
Choose `--template=notes` for the DB/validation/migration tutorial. English and
Japanese introductions, Getting Started, guides and examples follow the same
journey. The new PDFs use actual compiled code and condition-labelled Native
Threaded measurements rather than framework rankings.

## Upgrade and compatibility

1. Use Zig 0.17.0 and rebuild the CLI from the repository. Version 0.17 support
   shipped in v0.1.5; v0.2.0 keeps it and uses official external translate-c.
2. Review old Router/legacy Context/Middleware/HTTP Server use. These APIs and
   compatibility aliases are removed. Migrate to App/Context; see the upgrade
   guide for before/after examples.
3. Use `Context.setPrincipal` for identities. Untagged erased-pointer injection
   no longer satisfies typed Principal retrieval.
4. Handle Storage `InvalidCursor` and `InvalidLimit` in exhaustive error switches.
   New listPage results own their entries/metadata/cursor and require deinit.
5. Configure real D1 resource IDs before deploy. Deploy no longer creates
   placeholder resources or rewrites resource configuration.
6. Run `akamata update --to=v0.2.0 --sync`, review managed-file diffs and rebuild
   every target. Sync preserves/refuses user edits and never rewrites application
   source. Existing applications need their own source migration.

The tag's CLI scaffold initially pins the previous immutable v0.1.5 dependency
to avoid a self-referential archive hash. Main receives the exact v0.2.0 archive
hash after publication. When using the tagged CLI, run update to v0.2.0 after
init before copying ordinary-function guide code, or use the documented local
checkout override. The Hello bootstrap runs on either dependency.

## Validation scope

Release gates include full Linux/macOS CI, Threaded/private adapter Contracts,
stress/fault/isolation/session tests, Linux/macOS TSan, documentation examples,
strict generated TypeScript checking, PDF/link checks, real init/dev/test/check
journey, Native/Workers builds and scaffold/update/sync protection.
Gate run URLs and final archive hash are retained in the public release evidence.

Native production default remains **Threaded**. Native HTTP lifecycle includes
absolute write deadlines, bounded output and bounded I/O shutdown drain.
The refreshed public benchmark is a macOS M2 ReleaseFast loopback snapshot,
not performance certification or a cross-framework comparison.

## Known limitations

- Reactor remains **parked/fail-closed research code**, not an opt-in production
  feature. std.Io.Group was evaluated and not adopted.
- Offline adapter/WASM host fixtures are not live Cloudflare certification.
  No live provider test or automatic remote provisioning is claimed here.
- Named-environment migration remains fail-closed until resource resolution can
  be proved. Arbitrary custom Workers glue needs explicit host smoke evidence.
- Native socket streaming/WebSocket ownership and Workers DO gateway/HTTP
  buffering differ. Containers run Native providers and need durable storage
  configuration. Windows Native is not a tested platform.
- Raw pointer/tagged-union return inference is unsupported; use manual Context/
  Response. JavaScript number precision requires care for large integer IDs.

Release build archives contain the **chat example executable**, not the CLI.
Build/install the CLI from source with `./scripts/install.sh`.
