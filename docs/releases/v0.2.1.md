# v0.2.1 Performance & Reliability — release preparation

This is an unreleased draft. No v0.2.1 tag or GitHub Release is created by this
work; the published release and generated scaffold pin remain v0.2.0. The
package and development CLI version are prepared as 0.2.1.

## Highlights

- Native DB Pool supports nonblocking acquisition and absolute monotonic
  deadlines, explicit close, cooperative drain and acquisition metrics.
- Existing Prometheus observability can measure Threaded connection lifecycle
  and fixed-cardinality HTTP phases through explicit borrowed Counters owners.
- Buffered request tails are returned before another blocking socket read,
  fixing large keep-alive bodies that could wait for subsequent client input.
- Ordinary tagged-union JSON and enum literals are preserved in generated
  OpenAPI / TypeScript; one shared complex DTO fixture runs on Native and Workers.
- Reproducible paired benchmark, logical/backing allocation diagnostics, Pool
  saturation and deadline/release/close race coverage are retained with evidence.

## Compatibility

Existing `Pool.init`, indefinite `acquire`, `App.serve`, handlers and owned
responses remain supported. Optional metrics are disabled by default. Handle
ownership transfers only after successful Pool initialization. Stop new callers
before deinit and release leases first on the thread performing deinit; arbitrary
queries and CPU-bound handlers cannot be safely preempted.

Generated TypeScript enum types now accept enum literals instead of any string.
Callers that previously passed broad string variables must narrow them. Void
union payloads now use `Record<string, never>` instead of permissive `{}`. Tagged
unions now describe their existing standard JSON representation; custom tagged
union serializers are not inferred. Existing mapped-error body formats are kept.

## Known limitations

Native production remains Threaded. Reactor remains parked / fail-closed.
Workers synchronous HTTP streaming / SSE remains unsupported: safe asynchronous
producer ownership, backpressure and cancellation must be designed before a
ReadableStream bridge can reuse it. WebSocket transport and provider retry /
cancellation details retain explicit platform differences.

At the 1,024-connection admission boundary, echo P99 regression and a small
client-error rate remain unresolved; this draft does not certify saturated
throughput, error-free capacity or P99 parity. See the paired raw report.

Cloudflare evidence is offline adapter contract / WASM host simulation, not live
provider or production certification. Optional live workflows require isolated
test resources and credentials. No automatic remote provisioning is performed.
