# v0.2 Phase 1: one HTTP API and CLI boundaries

This is development toward v0.2, preserving portable application code across Native/VPS/Containers/Workers. CLI version output and generated dependency pins remain at the published stable v0.1.5; this work does not create a v0.2 release.

## Removed HTTP APIs

The HTTP path is `App → Context → endpoint/middleware → runtime`. No compatibility shim or deprecated alias remains for the removed API.

| Removed | Replacement |
|---|---|
| `am.Router(State)`, `am.Route` | App route methods or current compile-time registrations |
| `am.Ctx(State)`, `am.legacy` | `am.Context(State)` |
| Old `am.middleware` chain/Next/logger/recover | `am.Middleware(State)`, `am.Next(State)`, `am.mw`, App error handler |
| `am.Server(State)`, `am.http.Server`, `am.runNative` | `app.serve(options)`, `app.requestShutdown()` |
| `am.runtime.native` old Server wrapper | Current `src/serve.zig` transport |

Deleted `legacy_ctx.zig`, `router.zig`, `middleware.zig`, `http/server.zig`, and `runtime/native.zig` after confirming current App/serve did not depend on them. Old Router-only tests and historical redesign documents were removed. Middleware ordering and real-server GET/stream/deadline coverage moved to App tests; API-absence tests prevent compatibility exports returning.

Current `am.Routes`, static_router/static_middleware, typed endpoints, and HTTP primitives remain. Replace `ctx.app` with `c.state()`, and `ctx.json(status, value)` with `c.json(value, status)`, then register routes and serve through App.

Removed the unused `ServeOptions.read_timeout_ms` compatibility field; use header/body-specific deadlines. `write_timeout_ms` is explicitly documented as reserved and unenforced. A bounded write path remains future work.

## CLI modules

`main.zig` is now an approximately 140-line entry point. `help.zig` owns help/suggestions; `command/` owns init/build/dev/deploy/migrate/update/sync/db and inspection/generation/schema commands. `project/manifest.zig`, `scaffold.zig`, `templates.zig`, `managed_files.zig`, and `worker_glue.zig` own project content and protection. `process.zig` owns subprocess transport; `native.zig` shares POSIX filesystem ABI with the watcher.

Before/after binaries produced identical help/version/unknown-command output and exit codes, and identical generated files for eight target/capability combinations. Commands, arguments, watcher process groups/signals, and generated templates retain their behavior. Unit tests moved with their modules and remain aggregated from main.

Update/sync retain hash checks, dry-run, refusal of modified files, force backups, and manifest restoration on build failure. Recognition of old Workers template hashes and `sync-glue` are retained CLI safety behavior, unrelated to the removed HTTP API.

## Cloudflare operations

`command → cloudflare/operations.zig → wrangler.zig → process` exposes deploy and D1 create/list/execute/provision. `Location` and `ExecuteOptions` describe intent. Provider argv and output formats stay inside `cloudflare/`; configuration parsing/rendering is in `config.zig`. An injectable runner enables credential-free contract tests.

Wrangler is the sole default provider. D1 is created only for placeholder IDs; already-exists adopts a matching database from list output. Failed provisioning preserves config, and failed builds prevent deploy. Phase 2 can add provider selection here without distributing provider argv through commands/projects.

Existing `--containers` builds a Linux executable and local Docker image. There is no current Cloudflare Containers provisioning/publishing path to migrate; none was added.

## C bindings

| Approach | SQLite | OpenSSL | Decision |
|---|---|---|---|
| `std.Build.addTranslateC` | Target-specific vendored header translation | System header/pkg-config translation | Works in 0.17 but deprecated; removed |
| Official external translate-c | Follows vendored header and target | Follows installed version/include/link configuration | Adopted at a pinned commit |
| Checked-in generated bindings | Regeneration/ABI review for each target | OS/version/macro variants need maintenance | Rejected to preserve target portability |

Pinned [official Zig 0.17 branch](https://codeberg.org/ziglang/translate-c/src/branch/zig-0.17.x) commit `02ff0c523fb92a38939b04d0145c4a9602a74d56`, version 2.0.0, hash `translate_c-2.0.0-Q_BUWltOBwBYABF84EUL208pIFeUIwbBs29FmVBaafN5`. The package pins its transitive Aro dependency too. We do not track master.

`Translator.init` produces `sqlite3` and optional `openssl` modules; OpenSSL uses `link_system_libs` for ssl/crypto header discovery. Only Native invokes `b.lazyImport` and the lazy dependency. Workers-only builds neither fetch nor execute the translator. Initial Native builds need package fetching and host-tool compilation; prepopulate the Zig cache for offline builds.

Future upgrades must pin a matching branch/commit/hash and rerun SQLite, OpenSSL signing, Linux musl cross builds, Workers fresh-cache builds, and generated-project tests. The SQLite destructor C shim remains for ABI correctness.

Enum conversions were individually audited: HTTP/WebSocket wire values and contiguous metrics/trace counter indexes now use `@backingInt`/`@fromBackingInt`, retaining values and checked conversion semantics. See [official builtin documentation](https://ziglang.org/documentation/master/#backingInt). Historical 0.16 benchmark labels remain measurement conditions; current architecture descriptions of Server/C imports/outbound TLS were corrected.

## Validation

- Debug and ReleaseSafe unit/CLI/integration/tasks suites.
- Optional OpenSSL ReleaseSafe tests, including actual RSA SHA256 bytes against an OpenSSL reference and invalid PEM rejection.
- `cli-operations-test`: mock D1 create/adopt/failure/config protection, deployment order, db arguments, build/dev restart/shutdown/containers.
- `scaffold-local-test`, `project-update-test`, `workers-capability-sync-test`: generated Native/Workers builds, migration double-application protection, dry-run/refusal/backups/capability retention.
- Thirteen compile-fail cases and six Workers JavaScript contracts.
- Native/Workers examples, Linux musl cross build, Workers ReleaseSafe fresh-cache build, and package archive.

No live Cloudflare deployment/resource creation was performed. External-tool behavior is checked with mocks; Workers uses compilation and host contracts. CI adds CLI operation smoke and optional OpenSSL tests.

Native examples include chat/guestbook/bench/tasks/device_messaging; Workers entries exist for chat/guestbook/device_messaging. Tasks remains Native-only: building its Native entry for Workers fails on std.Io dependencies and needs future portable jobs/SSE work. Existing example Workers roots force ReleaseSmall; framework modules and generated Workers project roots are also validated in ReleaseSafe.

Fresh-cache checks also point `ZIG_LOCAL_PKG_DIR` at an empty path. Changing compile caches alone can leave project-local packages masking lazy-import errors. CI caught that issue; after switching to `b.lazyImport`, first-fetch Native and package-free Workers builds were verified.

Linux scaffold migration testing exposed a Darwin-only dirent layout in the loader. It now uses std.c platform directory APIs; the CLI uses the same standard definitions. A regression verifies complete filenames, lexicographic ordering, SQL contents, and migration-history double-application protection.

The tested macOS monotonic clock has 1µs resolution: an indexed SELECT can correctly measure 0ns, making the existing positive-duration Server-Timing assertion flaky. The test now uses a measurable recursive SQL workload and prints headers on failure.

## Phase 2 reevaluation

No Phase 2 feature changes are included. Detailed design should build on these findings:

1. Recheck official cf specifications, add provider selection/capability checks at Operations, and retain Wrangler default. Define unsupported/fallback behavior explicitly.
2. Form/multipart parsers and Context integration already exist, with fields/files/metadata/limits. Extend these rather than duplicate them. Bodies currently arrive buffered; design bounded stream/sink, cancellation, and partial-upload cleanup across Native transport/Workers bridge/Storage before large uploads.
3. Existing jobs are a Native DB-backed queue with periodic enqueue. A minimal App job registry plus timer/Scheduled Event adapters should be evaluated independently, with cron timezone/overlap/shutdown contracts and no distributed scheduler.
4. Native/Turso application-runner migrations and D1 SQL execution are separate. Design shared status/up protocol, configuration selection, D1 transactional history, and explicit pre-deploy execution before removing Workers scaffold request-time migrate.Once.
5. Reuse request tracing and metrics/request-ID/timing middleware plus platform clocks. Define consistent App configuration and error-recording order without a new framework or duplicate instrumentation.
